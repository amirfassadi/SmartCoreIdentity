# Development authentication runtime — 2026-10-10

Architecture A: Credential evidence is read without locks; Session commits acquire the Person issuance gate and never acquire `credential:*`. Registration Credential/Ready/ack transactions remain separate. Pending mutation, epoch mismatch, inactive Person, non-Ready registration or absent/inactive Credential deny issuance. Login verifies Argon2 using fixed supported work factors and rechecks the preverification epoch and Credential identity/hash under the gate before writing a Session. Unknown-contact login performs the same KDF work and returns the same outward unauthorized shape. Per-process HTTP admission remains a development limit, not distributed abuse enforcement.

## Opt-in surface

`Identity__AuthenticationEnabled=true` enables POST `/auth/login`, GET `/me`, POST `/auth/refresh` and POST `/auth/logout`. Default is disabled. All four require `X-Bff-Client-Key` matching `Identity__BffClientKey`; self/logout additionally require signed access Bearer. This is an authenticated **test BFF adapter**, not a browser cookie/CSRF implementation or production confidential-client authorization. No token is intended for browser JavaScript. The app continues to refuse Production startup. Reset/change/admin recovery endpoints do not exist.

Set a separate 32-byte base64 `Identity__AccessSigningKey`, distinct from the existing MAC/material keys, and a BFF client secret at least 32 characters. No values are committed. This development issuer uses standard IdentityModel JWT signing/validation (HS256 only, fixed issuer/audience, signature and lifetime checks, zero clock tolerance). The current key-version identifier is development-v1; managed rotation/JWKS/resource-server integration is still release work. The JWT package is pinned in dependency locks. [Microsoft JWT validation guidance](https://learn.microsoft.com/en-us/aspnet/core/security/authentication/configure-jwt-bearer-authentication?view=aspnetcore-10.0) is an implementation reference, not security approval of this custom development protocol.

The closed development wire subset is [authentication OpenAPI](../../contracts/authentication.openapi.yaml). Login accepts exactly one email/mobile and password, returning person and Session tokens. `expiresAt` is immutable Session expiry (login +86400 seconds); separate `accessExpiresAt` is at most issuance +900 seconds and never beyond Session expiry. Access expiry is rounded down to whole JWT seconds. Adding the separate deadline and required foreground assertion is a versioned development contract, not a silent change to upstream consumers.

Refresh requires `{refreshToken, foreground}` with foreground explicitly present and asserted by the authenticated test BFF. Current generation is consumed and one successor committed atomically with the internal RefreshTokenRotated fact. Only a successful foreground refresh updates idle evidence. Background rotation never extends the 30-minute foreground idle deadline. Absolute expiry never moves. Wrong-client or guessed secret does not revoke another family; a verified consumed predecessor before deadline closes its Session/family and commits RefreshTokenReuseDetected plus a separate latency observation. Grace is zero, including lost-response retry. Already revoked/expired families are uniformly unauthorized, with no successor disclosure. Concurrent presentations yield at most one successor, and the losing spent presentation revokes the family under the selected strict policy.

`/me` checks current Session/family eligibility, epoch and Person/Credential/Ready online. It does not renew idle. Logout binds request SessionId to the signed proof, closes Session/family atomically and writes one LogoutCompleted fact; same bound terminal replay returns 204 without rewriting closure evidence. Deadline expiry is recorded lazily on authenticated refresh/self/logout, with one SessionExpired fact; no autonomous Session sweeper is claimed. General external self-contained access may remain valid until JWT expiry; this adapter's online checks do not claim universal immediate invalidation.

## Events and measurement

Authentication public facts stay in a separate unpublished `auth_domain_event_outbox` because registration's unique registration/event key cannot represent repeated Sessions. LoginFailed preserves the pinned restricted Security-event contract, including contact and internal reason, while outward errors remain uniform. No failed-password value, JWT, refresh secret or verifier enters event payloads. Access logs must not be configured to capture sensitive headers/body. No broker/T16 delivery or real consumer compatibility is claimed.

Refresh security facts retain exactly the existing internal schema; they are separate from public facts/T16. The reuse latency observation is not proof of theft or lost response and does not enable grace. Audit retention and operational metric ownership must be selected before deployment; no automatic production audit purge is configured.

## Remaining password lifecycle

No reset/change intent can be activated through these routes. Future mutation admission must check proof, epoch, Credential guard and password policy before fencing/closing Sessions. `FailedClosed` remains blocked until an authenticated operator resolves authoritative Credential evidence and records reconciliation. Public reset requires both scheduled reconciliation and the operator recovery path to pass their own failure tests. Neither storage fixtures nor login tests replace those tests. Real-user onboarding stays closed until reset is delivered/accepted.

## Verification

The C# harness includes immutability regressions and authentication tests for Ready admission, uniform errors, signature/client rejection, generation rotation/reuse and races, logout replay, access/idle/absolute boundaries, foreground/background behavior, persistent fence denial and resolved-epoch eligibility.
